# FaceTrimStore: one holder for trims + unknown-version payload

Baseline review 2026-10-21.

RoundDoorBlockEntity.java:47-161 and RoundWindowBlockEntity.java:50-176 both hand-roll trims + unknownTrims + trimsEditable() + setTrims() + the fail-closed save/update-tag rule. DoorTrimNbt:29-43 and WindowTrimNbt:42-66 duplicate the read/write/version-check over FaceTrimsNbt (they differ only in tag name, version and the window 0.7.0 adapter).

Why: fail-closed on newer-version payloads is a save-safety property enforced in two copies; a third host copies it again. Also relieves RoundWindowBlockEntity, which carries appearance + trims + glass + sync.
Direction: FaceTrimStore in block/attachment/, parameterised by tag name and version, window legacy adapter as a pre-read hook; both entities delegate.

Outcome (0.9.0, commit a9885be): block/attachment/FaceTrimStore holds one slot's FaceTrims plus the unknown-payload custody, parameterised by a host Format (tag, version, saveEmpty: window writes explicit empty, door omits) and a load-time Legacy reader (the window 0.7.0 adapter, WindowTrimNbt.legacy). RoundDoorBlockEntity and RoundWindowBlockEntity delegate trims(), trimsEditable(), setTrims(), save, load and the update tag to it; DoorTrimNbt and WindowTrimNbt keep only their formats (and the window adapter). Saved payloads are unchanged (WindowTrim v2, DoorTrim v1). Covered by FaceTrimStoreTest, WindowTrimNbtTest, the save/reload GameTests and the unknown-payload migration GameTest.
